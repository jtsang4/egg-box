# 用户体验

本文讲用户看到和操作的部分：分流页、添加分流项、我的例外、解析方式、测试网址、连接列表与托盘、走向与节点选择、按环境切换、状态提示。

不在本文：方案有哪些、怎么更新和切换见 [方案](plans.md)；规则数据的格式和下载见 [规则来源](rule-sources.md)；这些设置怎么变成内核配置见 [生成配置](config.md)；节点怎么被认出来、怎么编辑导入的节点见 [节点](nodes.md)。

**关于文案。** 本文示例里的文案只是示意，界面用自己的措辞，例如本文的「暂不可用」在界面里是「尚未就绪」。行为按本文。

## 1. 首次使用

1. 用户导入第一个订阅。
2. 如果这个订阅附带分流方案，就直接采用它，并提示一次："已使用「机场A」附带的分流方案，可以在分流页切换。"
3. 如果没有附带方案，就使用[内置推荐方案](plans.md#5-内置推荐方案)。
4. 用户点连接，就能正常用。之后再导入的订阅不会自动切换方案（见[方案](plans.md#4-来源订阅的变化)）。

## 2. 分流页

导航里的"规则"改名为"分流"。页面从上到下依次是：

1. **标题栏。** 标题"分流"，副标题是"方案：内置推荐 · 12 个分流项"（内置推荐方案是 12 个分流项加兜底）。右侧有两个按钮：「测试网址」和「添加分流项」。
2. **方案栏。** 显示"当前方案 [内置推荐 ▾]"，旁边是来源说明，例如"跟随「机场A」更新 · 2 小时前"。菜单里有：另存为我的方案、恢复默认、删除（仅限"我的方案"）。
3. **我的例外。** 默认折叠，标题上显示条数。没有例外时显示一行提示："网站走错了？在连接列表里右键，或者在这里粘贴域名。"
4. **分流项列表。** 按生效顺序排列，每行包括：
   - 图标和名字；
   - 来源摘要，例如"MetaCubeX · 2 个来源 · 今天更新"；
   - 状态，只在有问题时显示：「3 天未更新」「暂不可用」「部分规则不支持」；
   - 走向，是一个下拉选择，见第 8 节；
   - 开关；
   - 行菜单：详情、上移 / 下移、删除（哪些分流项能移动和删除见[方案](plans.md#2-跟随更新的方案)）、复制到我的方案。
5. **兜底。** 固定在最后一行，显示为"其他所有流量 → [跟随主出口 ▾]"。

点击某个分流项，打开它的**详情**，内容包括：

- 每个来源的名称、所属项目、格式、条数（域名 x、IP 段 y）、不支持的条数及类型、最近更新时间、原始链接；
- 「添加来源」：把其他规则集合并进这个分流项，也可以添加手写条目；手写条目可以直接在详情里编辑；
- 「移除来源」；
- 「走向」下面的解析方式（第 5 节）；
- 被例外覆盖的提示（第 9 节）。

## 3. 添加分流项

「添加分流项」对话框有四个入口，选好之后进入同一个确认步骤。

**A. 搜索目录（默认入口）。** 输入"Netflix""AI""广告"这类关键词，结果按三类依次排列：

1. 目录里精选的条目，带中文名、简介、推荐来源，以及可选的其他来源；
2. MetaCubeX 的全部 geosite 名称（2019 个，见[规则目录](rule-sources.md#7-内置规则目录)），显示为"geosite: xxx"；
3. 其他项目的分类，比如 blackmatrix7 的约 670 个分类。

**B. 粘贴链接。** 支持 GitHub 页面地址（自动换成原始文件地址），也支持带镜像前缀的地址（自动识别出真实来源）。客户端下载后自动识别格式，并给出预览：

> 识别为 Clash 规则（classical），共 1,234 条：域名 1,100 · IP 段 130 · 其他 4。其中 4 条是 sing-box 不支持的类型（USER-AGENT），已跳过。

预览区分两种情况，各有一句说明："链接被换成了可读的真实地址"（GitHub 页面地址、镜像前缀），和"内容被转换了格式"。

如果粘贴的其实是订阅链接，提示"这看起来是一个订阅，要添加到订阅吗？"；如果下载失败，提示可以换镜像重试。

**C. 从其他方案添加。** 列出其他可用方案（内置推荐、各订阅附带的方案、我的方案）里的分流项，可以把单个分流项复制到当前方案。

**D. 手写条目。** 用户自己写一组规则，作为一个独立的分流项，比如"公司内网"的 10 个域名走直连。输入方式和"我的例外"的文本编辑相同（第 4 节）：可以每行一条，可以用 Clash 写法，也可以逐条选类型添加；只是手写条目不写去向。和例外的区别是：

- 一组手写条目共用同一个走向；
- 可以排在分流项中间的任何位置；
- 会随方案切换，不像例外那样全局生效。

已有分流项的详情里，「添加来源」也可以选"手写条目"，给现成的分流项补几条规则。比如给"AI 服务"补一个规则集里漏掉的域名。

**确认步骤**需要用户填三项：

- 名字：从目录条目或文件名预先填好，手写条目则由用户填写；
- 走向：按目录建议预选，比如广告类是"拦截"，国内类是"直连"，其余"跟随主出口"；
- 位置：默认按目录给的优先级插入（拦截类最前，具体服务排在公司大类之前，国内 / 国外大类排在最后），也可以选"放在 X 之前"。

## 4. 我的例外

- **适用范围。** 例外是全局的，不属于任何方案，永远最先匹配。
- **排序。** 按列表顺序匹配，用户可以排序。
- **单条添加。** 可以选类型：域名、域名后缀、关键字、正则、IP 段、端口、进程名、进程路径。添加一条已有的例外（类型和内容相同），是更新那一条，不重复列出；再次添加已有的匹配，不会清掉它的解析方式。
- **文本编辑。** 全部例外以文本打开，每行一条，行的顺序就是匹配顺序；改完整体保存，粘贴一批规则也在这里完成。写法是 Clash 的 `类型,内容,去向`，也可以只写域名、IP 段或程序名，由应用识别类型：`example.com` 识别为后缀，`1.2.3.0/24` 识别为 IP 段，`*.exe` 或程序名识别为进程。含逗号的字段用双引号括起来（内部的双引号写两次）。
  - 去向：`DIRECT` 是直连，`REJECT` 是拦截，`REGION:JP` 是某地区最快的节点，`NODE:节点名` 是某个节点；不写去向就跟随主出口。与某个分流项同名的去向，取该分流项此刻的走向（之后不跟着变）。
  - 解析方式：写在行的末尾，`dns=<服务器>` 或 `dns=exit`，见第 5 节。可以和 `no-resolve` 一起写，也可以不写去向。
  - 行首加 `#` 表示停用这条例外；不是完整规则的 `#` 行是注释，不会保存。
  - 同名节点：几个订阅有同名节点时，写成 `NODE:订阅/节点名`（订阅有简称就用简称）。已不存在的节点如果和现存节点同名，也会带上它原来的订阅名。打开时生成的去向文字，保存时只要没改，就沿用原来记下的节点，不再按名字查找，所以不会因为同名或改名而指错；写法和打开时某一行完全相同的去向，也指向同一个节点。新写或改过的节点去向必须能唯一找到一个节点，否则不能保存。
  - 保存前给出预览：新增、删除、修改的条数和顺序是否有变，列出将删除的例外、每个去向代表什么，以及有问题的行和原因（不认识的类型、重复、找不到或有歧义的节点、不认识的地区或去向、写错的或不起作用的 `dns=`）。有问题的行没处理好就不能保存；不认识的去向可以一键改为跟随主出口。
  - 已有例外按"类型 + 内容"对应，保存后保持原来的身份，连接列表里"命中例外 #n"不会错乱。只改 `dns=` 也算「修改」，身份不变。如果编辑期间例外列表被别处改过（比如从连接列表加了一条），不会直接覆盖：用户没动过的行换成最新内容，别处新加的例外补在末尾，用户改过的行保持不变，再请用户检查后保存。
- **复制为规则。** 单条例外可以复制成上面的一行文本（带上解析方式），粘回文本编辑能原样还原。
- **走向。** 与分流项的走向选项相同。把例外改成拦截时保留它的解析方式（拦截时它不起作用，见第 5 节）。
- **从连接列表生成。** 在一个连接上右键，选择"以后……走"，可以选择作用范围：
  - 只针对这个域名；
  - 整个主域名，用公共后缀表判断；
  - 这个 IP；
  - 这个程序。

  再选走向，就生成一条例外，并立即生效。

## 5. 解析方式

凡是有走向的地方（每条例外、每个分流项），都可以设置**解析方式**。它决定这条规则匹配的域名用哪个 DNS 服务器解析。取值和含义在两处完全相同：

| 文本写法 | 界面名称 | 含义 |
|---|---|---|
| 不写 | 默认 | 分流项按它是不是国内选国内 DNS 或远程 DNS；例外是直连的用国内 DNS，其余用远程 DNS（见[生成配置 · DNS](config.md#3-dns)） |
| `dns=<服务器>` | 指定服务器 | 用这个服务器解析，查询**经过这条规则自己的出口**。服务器的写法和设置页的 DNS 相同：`10.0.0.53`、`udp://…`、`tcp://…`、`tls://…`、`https://…`，以及 `system`（系统当前的 DNS）。保存时统一成一种写法（`udp://1.1.1.1:53` 存成 `1.1.1.1`，`TLS://DNS.x:853` 存成 `tls://dns.x`，IPv6 地址用小写的标准写法），写法不同但指的是同一个服务器，就算同一个 |
| `dns=exit` | 由出口解析 | 本地不解析：只对这条规则的域名返回 fake-ip 地址，连接时再换回域名，交给出口那一端解析 |

- **例外**：写在文本行的末尾，例如 `DOMAIN-SUFFIX,corp.example,DIRECT,dns=10.0.0.53`、`DOMAIN-KEYWORD,intra,NODE:Gateway,dns=exit`。可以和 `no-resolve` 一起写，也可以不写去向（`DOMAIN-SUFFIX,a.com,dns=exit` 表示跟随主出口、由出口解析）。「复制为规则」会带上它，粘贴回去能原样还原。单条例外的对话框里也能设置。
- **分流项**：在详情页「走向」下面设置，一个分流项一个值。手写条目和规则集来源都适用。编译后没有域名规则的分流项（或者还没编译、只有手写 IP、端口、程序条目的分流项）不显示这个设置。
- **方案**：在跟随更新的方案里，解析方式像走向一样记在用户的叠加层上，见[方案](plans.md#2-跟随更新的方案)。
- **校验**：服务器要么是 IP 地址，要么是带点的主机名；`localhost` 不行，本机请写 `127.0.0.1` 或 `::1`。`dns=exti`、`dns=sytem`、`dns=10.0.0.256` 这类笔误会被标出来，不会当成一台叫这个名字的服务器。设置页的 DNS 不受这条限制，和以前一样。IP 段、端口、程序这类规则不查 DNS，写了 `dns=` 时保存预览会把这一行标为有问题，原因是这个选项在这里不起作用。服务器写错了也标出来。只改 `dns=` 也算「修改」，例外原来的身份不变。在分流项的手写条目里粘贴带 `dns=` 的行，这一行会被标出来，不会悄悄丢掉：分流项的解析方式只在详情里设一次，对所有条目生效。
- **`system` 不经过出口**：系统 DNS 只能在本机查询。
- **走向是拦截时**，解析方式不起作用，这些域名的查询直接被拒绝。

解析方式和走向不会冲突：一个域名由哪条规则决定走向，就由同一条规则决定用哪个 DNS（见[生成配置 · DNS](config.md#3-dns)）。

## 6. 测试网址

输入一个网址、域名或 IP，界面告诉你：

> 命中「AI 服务」（来源：MetaCubeX category-ai-!cn）→ 美国·自动 → 当前是「洛杉矶 02 · 机场A」，140ms

旁边有一键操作：「改为直连」「改为主出口」「改为……」，点了就生成一条例外。

- 如果需要按 IP 判断，就先解析域名，并标注"按解析结果"。
- 查不到的域名拒绝作答，和内核的行为一致，不猜结果。例外：第一条匹配这个域名的规则如果指定了自己的 DNS 服务器（`system` 除外，它就是测试网址自己用的解析），而本机的 DNS 解析不了这个域名，测试网址不会因此说「拒绝」，而是按域名继续匹配：那个服务器可能能解析，测试网址没法替内核去问它。
- 连接处于全局或直连模式时，按模式回答，而不是按方案。
- 局域网直连和内核按同样的规则回答：「有地址是私有的，并且没有地址被认领」才算命中局域网直连，和内核的逻辑规则一致（认领见[生成配置](config.md#21-局域网直连与用户认领的私有地址段)）。
- 端口和进程类规则没法用网址测试，标注"不适用"即可。
- 未连接时也能测试，只是不显示当前实际节点。

## 7. 连接列表、首页、托盘

- **连接列表。** "命中规则"一列显示用户能看懂的名字："AI 服务""例外 #3""兜底""局域网"，不显示内核的原始规则文本。出口一列显示节点；遇到重名节点时附上订阅名。右键菜单里有"以后……走"，见第 4 节。
- **首页。** 当前出口卡显示主出口及实际使用的节点。
- **托盘面板。** 显示主出口，可以快速切换：自动、地区自动、最近用过的节点。节点重名时附上订阅名。

## 8. 走向与节点选择

所有地方的走向下拉都是同一套选项：

```
跟随主出口（自动 · 当前 香港 03 · 机场A）
直连
拦截
地区自动        ▸  香港（12）  日本（8）  美国（10） …
指定节点        ▸  可搜索的列表，按订阅分段：节点名 · 延迟
```

**主出口**可以是：

- 自动：所有可以参与自动选择的节点里最快的那个；
- 地区自动；
- 指定节点。

**地区自动：**

- 选该地区里最快的节点。如果该地区只有一个节点，就直接用它。
- 订阅刷新、节点改名、换密码都不受影响。这是推荐给大多数人的选项。

**指定节点：**

- 订阅刷新后按"订阅 + 节点名"找回（见[节点身份](nodes.md#1-节点身份)）。
- 默认打开"不可用时临时用同地区最快的节点"。被临时替换时，在节点页和托盘提示："你为「AI 服务」指定的「东京 03 · 机场A」不可用，临时使用「东京 05 · 机场A」。"（怎么实现、有什么限制见[生成配置 · 出口结构](config.md#1-出口结构)。）
- 如果节点已经从订阅里消失，同样临时用同地区最快的节点，并提示 [重新选择] [知道了]。指定的节点不会被静默清除。

**节点页：**

- 顶部是主出口条：自动卡片、地区自动卡片、当前指定的节点。卡片放不下的地区，在"更多地区"菜单里仍然可以选。
- 主出口条下面有一行"分流项正在使用"，列出走向不是"跟随主出口"的分流项及其实际节点，例如："AI 服务 → 洛杉矶 02 · 机场A（140ms）"。
- 筛选除了按地区，还可以按订阅。
- 节点卡片上始终显示订阅名。
- 卡片右键菜单：
  - 设为主出口；
  - 用于分流项……；
  - 不参与自动选择；
  - 设置地区……（自动识别错误时手动更正）；
  - 复制名称；
  - 导入的节点另有「编辑链接…」，见[节点](nodes.md#2-编辑导入的节点)。

**订阅设置**里增加两项："参与自动选择"开关（默认开），以及短别名，用于"节点名 · 订阅名"的显示。原有的按名字包含 / 排除节点的正则保留不变。

## 9. 按环境切换

切换环境不加新概念：基于内置方案「另存为我的方案」，加几个手写分流项，每个设好走向和解析方式，在不同环境下开关对应的分流项即可。例如：

| 分流项 | 走向 | 解析方式 | 内容 |
|---|---|---|---|
| 内部网络 · 直接接入 | 直连 | 内部 DNS 的 IP，或 `system` | 内部域名 |
| 内部网络 · 经节点 | 能进入该网络的节点 | 由出口解析 | 内部域名、内部地址段 |

内部地址段写在手写条目里就能优先于局域网直连（[认领](config.md#21-局域网直连与用户认领的私有地址段)）。这样「一个小段 → 直连」写在前、「包含它的大段 → 某个节点」写在后，就能直接生效，不用关掉全局开关。

例外是全局的，并且排在所有分流项前面，所以随环境变化的规则不应该写在例外里。为此加一个**覆盖提示**：分流项的手写条目被某条已启用的例外完全覆盖时（同一条，或者例外的后缀、关键词、IP 段包含它），详情页提示「被例外 #n 覆盖」，并说明走向和解析方式都以例外为准。只比较手写条目；规则集来源的内容不展开比较。

## 10. 状态与提示

| 情况 | 提示方式 |
|---|---|
| 某个来源更新失败 | 分流项那一行显示「N 天未更新」，继续使用上一份 |
| 某个分流项完全没有数据 | 行上显示「暂不可用」，生成配置时跳过它，不阻止连接；如果是启用中的分流项，连接后提示一次 |
| 部分规则不支持 | 行上显示「部分规则不支持」，详情里列出类型和条数 |
| 指定节点被临时替换或已消失 | 节点页横幅，加一次通知 |
| 订阅方案的分流项有增减 | 提示一次 |

## 11. 暂不做

- 托盘里直接开关「我的方案」的分流项。
- 粘贴一段带不同去向的规则（例如其他代理工具配置里的规则段），按去向自动拆成几个分流项。
