# 数据与迁移

本文讲分流相关的保存数据：版本规则、从旧版本的一次性迁移，以及分流状态格式 1 → 2 时补上的"用户写的"标记。

不在本文：这些数据在界面上的含义见 [用户体验](experience.md)；"用户写的"标记在生成配置时怎样起作用见 [生成配置](config.md#21-局域网直连与用户认领的私有地址段)；节点身份和导入节点的原始链接怎样保存见 [节点](nodes.md)；规则来源的更新记录（更新时间、ETag、内容哈希）见 [规则来源](rule-sources.md#6-更新)。

## 1. 数据格式的版本

新的数据结构（方案、分流项、来源、例外、节点身份）都要带版本号，迁移只能执行一次，而且必须可以重复执行而不出错。

## 2. 从旧版本迁移

升级后第一次启动时，自动执行一次迁移：

| 原有设置 | 迁移为 |
|---|---|
| 路由预设：国内直连（`china`） | 内置推荐方案 |
| 路由预设：全部代理（`proxy-all`） | 内置推荐方案，"国内网站"改为"跟随主出口" |
| 路由预设：仅代理国外（`foreign-only`） | 内置推荐方案，兜底改为"直连" |
| 拦截广告（`BlockAds`） | 开启"广告拦截"分流项 |
| 局域网直连（`LANDirect`）、IPv6 | 移到设置页的"网络"部分，含义不变 |
| 自定义规则 | 按原顺序变成"我的例外"。代理映射为"跟随主出口"，直连映射为"直连"，拒绝映射为"拦截" |
| `SelectedNode` 是节点哈希 | 按哈希找到节点，转成节点身份，作为主出口的指定节点；找不到就设为"自动"，并提示一次 |
| `SelectedNode` 是 `region-XX` 或空 | 主出口设为该地区自动，或者"自动" |
| 地区分组开关（`RegionGroups`） | 删除，地区自动始终可选 |
| 规则数据镜像、更新频率 | 保留 |

已经下载的 SagerNet 规则数据不再使用。新方案需要的数据，在第一次连接前按[下载与镜像](rule-sources.md#5-下载与镜像)的方式下载。

## 3. 分流状态格式 2：用户写的标记

局域网直连只让出用户亲手写下的私有地址段（[生成配置](config.md#21-局域网直连与用户认领的私有地址段)），所以每个来源要分清哪些条目是用户写的：

- 来源上记一个「用户写的」标记。订阅方案导入时带来的内联条目不算用户写的。用户编辑这样的来源时，原来就有的私有段记为「继承的」；只有用户新加的段才算用户写的。
- 升级时（分流状态的格式 1 → 2，资料库文件的格式不变，旧版本仍能打开）给以前的手写来源补上标记，按来源编号的格式区分：用户写的来源编号是随机生成的，订阅导入的是按内容算的哈希。
- 这一步每次读入都做（只补不删），所以退回旧版本又升级回来，旧版本丢掉的标记也会补回来。
- 在旧版本里编辑过的订阅来源分不清哪些是用户加的，按订阅的算，不认领；用户编辑过的订阅来源在退回旧版本再升级后也是这样。
