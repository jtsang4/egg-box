# 概述：为什么改、目标、概念、约束、已定决策

本组文档是 EggBox 分流（原"规则"）和节点选择的完整设计，用来替换原来的三个路由预设、自定义规则列表和单一的节点选择。实现时以这组文档为准，`docs/design.md` 里的进程架构和安全边界保持不变。

本文讲为什么要这样设计、要守住什么。具体的界面、格式、配置生成分别见 [README](README.md) 里列出的各篇。

## 1. 为什么要改

### 1.1 第一轮：分流和节点选择

原来设计的问题，都是从用户实际使用时发现的：

- **只能选"代理 / 直连 / 拦截"。** 最常见的需求，比如"AI 走美国、Netflix 走新加坡、其余走香港"，原来做不到。
- **用不了社区规则集。** 原来只认 SagerNet 的 4 个固定规则集，没有地方填链接。教程、朋友、机场给的规则（blackmatrix7、Loyalsoldier、ACL4SSR、anti-AD 等）都导不进来，只能一条条手写。
- **订阅自带的分流方案被丢掉。** 很多机场的订阅（sing-box 或 Clash 格式）带有完整的分组和规则，原来导入时只留下节点。
- **规则一次只能加一条。** 不能批量粘贴，不能单条停用，也看不到预设实际展开成了哪些规则。
- **固定的节点会悄悄失效。** 节点身份是整份节点配置的哈希，服务商轮换密码或 IP 后哈希就变了。这时选择会静默回到"自动"，用户不知道。
- **重名节点分不清。** 多个订阅里有同名节点时，除了节点页，其他地方都看不出它来自哪个订阅。

### 1.2 第二轮：内部网络与按环境切换

第一轮实现之后又加了一轮设计（解析方式、私有地址段认领、按环境切换）。一类常见需求：某个内部网络的域名只有它自己的 DNS 能解析，而用户会从不同的地方访问它。例如：

- **直接接入时**：内部域名直连，必须用内部 DNS 解析。公网直连的域名照常用国内 DNS，走代理的用远程 DNS。
- **不在这个网络里时**：内部域名和内部地址段都交给一个能进入这个网络的代理节点。这些域名在公网上查不到，只能由节点那一端去解析。

第一轮的设计做不到，原因有三：

1. 只有「国内 DNS」「远程 DNS」两个服务器，不能按规则指定解析用的服务器。
2. 走节点的域名一律经主出口向远程 DNS 解析。内网域名在公网上查不到，TUN 模式下应用拿不到地址，连接根本发不出去。
3. 「局域网直连」排在所有规则前面，「某个私有地址段 → 某个节点」这样的规则永远不会生效。

而且这些设置要能**随规则一起切换**：换环境时只开关几个分流项，不用去设置页改 DNS。

这一轮的结果分别写进了：[解析方式](experience.md#5-解析方式)（界面和写法）、[生成配置](config.md)（DNS 和局域网直连）、[按环境切换](experience.md#9-按环境切换)。

## 2. 目标与原则

1. **小白零配置。** 导入订阅、点连接，就有合理的分流：国内直连、国外代理，常见服务各归其类。
2. **社区规则直接可用。** 热门项目的规则集，不管是 sing-box、Clash、Surge 还是 AdGuard 格式，都能直接添加，用户不需要知道格式差别。
3. **从用户的问题出发。** "这个网站走错了"应该能直接改，而不是让用户去想"该写一条什么规则"。
4. **选择不会悄悄丢失。** 订阅刷新、节点改名、换方案时，尽量保住用户的选择。真的保不住时，明确告诉用户。
5. **安全边界不变。** agent 仍然不主动联网，只接受 GUI 交来的资源；订阅内容仍然按凭据对待。

非目标：需要解密 HTTPS 的规则（URL-REGEX、USER-AGENT）、脚本和重写、负载均衡。

## 3. 概念

| 名称 | 含义 |
|---|---|
| 节点 | 订阅里的一个代理服务器。所有已启用订阅的节点合在一起使用，可以叠加。 |
| 主出口 | 默认的出去方式：自动（最快）、某地区自动，或指定节点。托盘和首页显示的就是它。 |
| 分流方案 | 一张有序清单：我的例外 → 分流项 → 兜底。**同一时间只有一个方案生效。** |
| 分流项 | 一类流量，例如"AI 服务"。由名字、图标、一个或多个规则来源、一个走向组成，可以单独开关。 |
| 规则来源 | 分流项背后的规则数据：一个规则集文件（任意受支持的格式），或几条手写条目。 |
| 走向 | 某类流量的去处：跟随主出口、某地区自动、指定节点、直连、拦截。 |
| 解析方式 | 有走向的地方（例外、分流项）都可以设置：这条规则匹配的域名用哪个 DNS 服务器解析。见 [解析方式](experience.md#5-解析方式)。 |
| 我的例外 | 用户自己的规则，独立于方案，永远排在最前面，切换方案也不会丢。 |
| 兜底 | 没有命中任何规则的流量，它的走向。 |
| 规则目录 | 应用内置的可搜索目录，收录热门规则集项目里的常见分类。 |

用户界面里不出现"规则集""策略组""srs""behavior"这些词。用户只会看到"分流项""来源""走向"。

## 4. 约束

- **订阅内容按凭据对待。** 包括节点名、服务器和分组成员。日志、诊断报告、测试输出里都只记录数量和类型。用真实订阅做的测试，必须显式开启才运行，订阅链接通过文件路径传入，不能进仓库。
- **规则集链接和规则内容不是机密**，可以正常记录。但链接里的镜像前缀不能用来推断用户身份；带查询参数的链接，在显示和诊断报告里隐藏参数。
- **GUI 只交资源，不交下载地址。** GUI 交给 agent 的配置里，规则集一律是本地资源；agent 依然拒绝远程规则集。
- **数据格式要标版本。** 见 [数据与迁移](data-and-migration.md#1-数据格式的版本)。

## 5. 已定决策

| 决策 | 理由 |
|---|---|
| 同一时间只有一个分流方案生效，节点可以叠加 | 内核只有一张规则表，合并多个方案会造成看不见的冲突 |
| 默认数据源用 MetaCubeX meta-rules-dat sing 分支 | 有服务 IP 段、每日更新、和订阅模板命名一致 |
| 客户端把所有格式统一编译为 .srs | sing-box 只支持 srs 和 JSON；同时解决版本兼容和资源数量问题 |
| 订阅方案只取分类和规则，不绑定这个订阅的节点 | 常见模板的分组本来就是"主选择 + 全部节点 + 直连"，不丢信息；而且跨订阅可用 |
| 第一个订阅带方案时自动采用，之后不自动切换 | 让导入即可用，同时避免后来的订阅打乱用户已经调好的方案 |
| 广告拦截默认关闭 | 和原来一致；误拦截比漏拦截更伤用户体验 |
| 微软、苹果默认直连 | 国内能直接访问，直连下载更快；和常见模板一致 |
| 每个分流项一个选择器 | 改走向不需要重启内核，符合 `design.md` 里"切换节点优先调用选择接口"的原则 |
| 跟随更新的方案不能删除自带分流项，也不能调整它们的顺序 | 订阅刷新时能可靠地合并用户的修改；需要完全控制就另存为我的方案 |
| 分流项用哪个 DNS 由它是不是国内决定，不随当前走向变 | 走向要能在运行时切换，而按走向选 DNS 就要重新生成配置。详见 [生成配置 · DNS](config.md#3-dns) |
| 局域网直连仍排在最前，只让出用户亲手写下的私有地址段 | 把局域网直连整个后移时，方案里的规则会抢走局域网流量。详见 [生成配置 · 局域网直连](config.md#21-局域网直连与用户认领的私有地址段) |
| 「系统路由」走向暂缓 | 按 sing-box 的网卡绑定逻辑，需要它的场景比设想的少，而且每次开关都要重建 TUN。详见 [生成配置 · 系统路由](config.md#5-系统路由验证结论暂缓) |
