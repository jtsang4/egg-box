# 方案

本文讲分流方案：有哪几种、为什么只能选一个、跟随更新的方案能改什么、刷新和切换时怎样保住用户的选择、来源订阅停用或删除时怎么办，以及内置推荐方案的内容。

不在本文：方案栏和分流页的界面见 [用户体验](experience.md#2-分流页)；订阅里的分组和规则怎样变成方案见 [订阅附带的方案](subscription-plans.md)；方案里的规则数据从哪里下载见 [规则来源](rule-sources.md)。

## 1. 方案的种类

可用的方案有三种：

| 方案 | 来源 | 更新 | 结构能否修改 |
|---|---|---|---|
| 内置推荐 | 应用自带 | 随应用版本更新 | 能改走向和开关；能在清单里添加自己的分流项 |
| 「机场X」的方案 | 订阅附带 | 跟随订阅刷新 | 同上 |
| 我的方案 | 用户另存 | 不自动更新 | 完全自由 |

**分流方案只能选一个。** 启用多个订阅只会叠加节点，不会叠加方案。原因是内核同一时间只有一张规则表，从上往下第一条命中的规则生效。如果把多个方案硬合并，排在前面的方案说了算，后面的大部分规则不会生效，用户却看不出来。

## 2. 跟随更新的方案

内置推荐和订阅附带的方案会跟随更新：

- 方案自带的分流项可以改走向、开关和解析方式，但不能删除，也不能调整顺序。
- 用户自己添加的分流项会作为叠加层保留：可以排序、删除，用"放在 X 之前"锚定位置。如果锚点被方案删掉了，就放到兜底之前。
- 用户对方案自带分流项的走向、开关和[解析方式](experience.md#5-解析方式)都记在叠加层上，按分流项的名字对应。「恢复默认」会清除这些设置，包括解析方式；分流项菜单里的「恢复方案的选择」也会恢复解析方式。
- 需要完全控制时，选「另存为我的方案」。另存时带上解析方式。

## 3. 方案内容变化与切换方案

**订阅刷新、方案内容变了：**

- 用户对每个分流项设置的走向、开关和解析方式，按分流项名保留。
- 新增的分流项默认"跟随主出口"，并提示一次："「机场A」的方案新增了 2 个分流项。"
- 被删掉的分流项也提示一次。

**切换方案：** 同名分流项的走向和解析方式沿用。比较名字时忽略开头的 emoji 和空白，并且不区分大小写。比如"💬 AI 服务"和"AI 服务"会被当作同一个。

## 4. 来源订阅的变化

**来源订阅停用或删除：**

- 订阅停用：方案继续可用，因为已经下载的规则数据还在。方案栏提示"来源订阅已停用，不再更新"。
- 订阅删除：方案自动转成"我的方案（来自已删除的「机场A」）"。

**新导入带方案的订阅时：** 如果它是第一个订阅，就自动采用它的方案；否则不切换，只在订阅卡片上显示"附带分流方案 · 17 个分流项 [使用]"。

## 5. 内置推荐方案

数据来源统一用 MetaCubeX/meta-rules-dat 的 sing 分支。选它的原因：

- 它有 Telegram、Google、Netflix 等服务的 IP 段，官方 sing-geoip 只有国家维度的数据；
- 每天更新；
- 和大量订阅模板用的是同一套名字，订阅方案和内置方案引用同一个文件时，只需要下载一次。

方案共 12 个分流项，加兜底：

| # | 分流项 | 来源（geosite / geoip） | 默认走向 | 默认开启 |
|---|---|---|---|---|
| 1 | 广告拦截 | geosite category-ads-all | 拦截 | 否 |
| 2 | AI 服务 | geosite category-ai-!cn | 跟随主出口 | 是 |
| 3 | Telegram | geosite telegram；geoip telegram | 跟随主出口 | 是 |
| 4 | YouTube | geosite youtube | 跟随主出口 | 是 |
| 5 | 流媒体 | geosite netflix、disney、hbo、primevideo、spotify；geoip netflix | 跟随主出口 | 是 |
| 6 | Google | geosite google；geoip google | 跟随主出口 | 是 |
| 7 | 社交媒体 | geosite twitter、facebook、instagram、tiktok；geoip twitter、facebook | 跟随主出口 | 是 |
| 8 | GitHub | geosite github | 跟随主出口 | 是 |
| 9 | 微软 | geosite microsoft | 直连 | 是 |
| 10 | 苹果 | geosite apple | 直连 | 是 |
| 11 | 国内网站 | geosite cn；geoip cn | 直连 | 是 |
| 12 | 国外网站 | geosite geolocation-!cn | 跟随主出口 | 是 |
| — | 兜底 | — | 跟随主出口 | — |

排序原则是范围窄的在前：YouTube 排在 Google 前面，GitHub 排在微软前面，大类排在最后。

原来的三个预设，变成了这个方案里的走向选择（升级时怎样迁移见[数据与迁移](data-and-migration.md#2-从旧版本迁移)）：

- 原"国内直连"预设，就是默认状态；
- 原"全部代理"预设，相当于把"国内网站"改成"跟随主出口"；
- 原"仅代理国外"预设，相当于把兜底改成"直连"。
