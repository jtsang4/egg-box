# 分阶段交付与验收

本文讲这套设计分几个阶段交付，每个阶段包括什么、怎样验收。

不在本文：每项功能本身的设计见各篇（[README](README.md)）。编辑导入节点的验收和它的设计放在一起，见 [节点](nodes.md#23-验收)。

## 第一轮

### 阶段一：新模型和内置方案

**内容：**

- [节点身份](nodes.md#1-节点身份)，重名节点显示订阅名；
- 指定节点失效时明确提示；
- 方案、分流项、走向、兜底、我的例外的数据模型，以及[迁移](data-and-migration.md#2-从旧版本迁移)；
- [内置推荐方案](plans.md#5-内置推荐方案)；
- 新的分流页：方案栏只有"内置推荐"一项，提供分流项的走向和开关，例外的增删改，以及由手写条目组成的分流项（可插在任意位置）；
- 每个分流项一个选择器，运行时切换走向；
- 规则来源处理流程：先支持 .srs 和 sing-box JSON；
- agent 资源上限调到 256。

**验收：**

- 从旧版本升级后，三种预设、自定义规则、已选节点都迁移正确，可以连接；
- 分流项在非拦截走向之间切换时不重启内核；
- 订阅刷新后节点密码变了，指定节点仍然有效；节点被删除时，界面上有明确提示。

### 阶段二：社区规则集

**内容：**

- 内置目录和搜索；
- 粘贴链接；
- [支持的格式](rule-sources.md#3-支持的格式)中的全部格式，以及 .mrs 对应表；
- 镜像前缀识别和下载策略；
- 分流项详情，以及多来源合并。

**验收：**

- [规则目录](rule-sources.md#7-内置规则目录)"收录的项目"表里的每个项目，至少各添加一个规则集成功；
- Clash classical 列表里不支持的类型，计数正确；
- 点号规则按 Clash 和 Surge 各自的语义匹配正确，用单元测试覆盖；
- 未连接、且 GitHub 不可达时，能通过 jsDelivr 拿到数据。

### 阶段三：订阅附带方案

**内容：**

- sing-box 和 Clash 订阅的[方案导入](subscription-plans.md)；
- 方案切换，同名分流项的走向沿用；
- 跟随订阅更新；
- 用户叠加层；
- 另存为我的方案；
- 从其他方案添加分流项；
- 来源订阅停用或删除时的处理。

**验收：**

- [订阅附带的方案](subscription-plans.md#4-实例)里的真实订阅，sing-box 链接和 Clash 链接得到相同的 17 个分流项和相同的走向。这项测试要显式开启才运行，日志只记录数量；
- 同时启用两个带方案的订阅时，只有一个方案生效，节点合并显示；
- 订阅刷新后方案增减了分流项，用户的走向选择保留，并有提示。

### 阶段四：使用体验

**内容：**

- 测试网址；
- 从连接列表生成例外；
- 例外和手写分流项的批量粘贴（带预览），包括 Clash 写法；
- "首选节点 + 同地区备用"的组类型；
- 不参与自动选择；
- 手动设置地区；
- 连接列表显示易懂的命中原因；
- 托盘重名节点加订阅名。

**验收：**

- 测试网址的结果和真实连接命中的规则一致，用一组域名和 IP 对照验证；
- 首选节点断开后，流量自动切到同地区的其他节点，恢复后切回。

## 第二轮：解析方式与按环境切换

内容见[解析方式](experience.md#5-解析方式)、[按环境切换](experience.md#9-按环境切换)、[DNS](config.md#3-dns) 和[局域网直连](config.md#21-局域网直连与用户认领的私有地址段)。

**验收：**

- 例外文本：`dns=` 的读、写、往返，和 `no-resolve`、`NODE:`、正则、引号一起使用；错误值和非域名规则上的 `dns=` 都在预览里标出；只改 `dns=` 计为修改，身份不变。
- 分流项：在我的方案和跟随更新的方案里设置、清除解析方式；切换方案和刷新方案时保留；另存为我的方案时带上。
- 生成配置：默认解析方式的输出不变；指定服务器的 DNS 服务器和 detour 正确（直连不设 detour，分流项指向自己的选择器）；以域名到达的连接也用这个服务器解析；fake-ip 只作用于对应的域名；resolve 规则排除由出口解析的域名；局域网直连让出用户认领的私有段，其他私有地址照旧直连；真实内核能加载生成的配置。
- 测试网址按新的顺序回答。
- 界面：分流项详情和单条例外对话框能设置解析方式，两种语言；编译后没有域名规则的分流项（或者还没编译、只有手写 IP、端口、程序条目的分流项）不显示这个设置；从「添加例外」再次添加已有的匹配，不会清掉它的解析方式；把例外改成拦截时保留它的解析方式；分流项菜单里的「恢复方案的选择」也恢复解析方式；覆盖提示能显示。
