# 节点

本文讲节点怎样被认出来（节点身份）、怎样编辑导入的节点，以及怎样为节点和订阅配置两跳中转。

不在本文：主出口、地区自动、指定节点这些选择在界面上怎样操作、节点页长什么样，见 [用户体验](experience.md#8-走向与节点选择)；节点在配置里怎样组成选择器和自动组，见 [生成配置](config.md#1-出口结构)；旧版本的节点哈希怎样迁移成节点身份，见 [数据与迁移](data-and-migration.md#2-从旧版本迁移)。

## 1. 节点身份

- **身份由什么构成**：订阅 ID + 节点名，同一订阅里出现重名时再加序号。另外记录节点配置的哈希和最后一次识别到的地区，作为兜底信息。
- **订阅刷新后找回的顺序**：先按"订阅 + 名字"找；找不到就按哈希找（应对改名但配置没变的情况）；还找不到，就视为"已消失"，按[指定节点](experience.md#8-走向与节点选择)的规则处理。
- **用到身份的地方**：主出口、分流项走向、"不参与自动选择"、手动设置的地区，都保存这个身份，而不是生成配置时的 tag。
- **tag 只在配置内部使用**：生成配置时，tag 仍然从名字派生并保证唯一，但不对外暴露。

## 2. 编辑导入的节点

「导入节点」导入的是一份不会自己更新的节点列表（`KindLocal`）。原来导入之后，只能改这份导入的名称、简称、是否参与自动选择和节点名过滤，**看不到节点本身的配置，也改不了**，想改端口之类的只能删掉重新导入，分流里指定这个节点的地方也要重新选。

### 2.1 做法：保留并编辑原始链接

不为每种协议做一套字段表单，而是保留节点导入时的**原始分享链接**（例如 `socks5://127.0.0.1:1080#Gateway`），编辑的就是这条链接：

- **保存什么**：从分享链接导入的节点，同时记下这一行原文（`Node.Link`），和节点配置存在同一个节点文件里。节点配置本来就带着密码等凭据，原文的敏感程度相同，不另外存放。**订阅里的节点不保存原文**：它们不能编辑，原文只会是凭据的又一份副本，所以订阅更新时会去掉。
- **从哪里编辑**：节点页里，导入节点的菜单有「编辑链接…」；订阅页里，导入那张卡片的菜单有「编辑节点…」，只有一个节点时直接打开，有多个时先选节点。卡片菜单列出这份导入里存着的**全部**节点，包括导入已停用、或者被节点名过滤掉的：修好某个节点，可能正是停用或过滤它的原因。订阅来的节点不提供编辑：改了也会被下一次订阅更新覆盖。
- **怎么保存**：只接受一条分享链接。解析失败、协议不支持、和这份导入里另一个节点重名或完全相同时不保存，原来的节点保持不动，并说明原因；说明里不引用链接内容，因为链接带着凭据。保存只替换这一个节点，所在的导入不变。替换节点和更新分流里对它的选择在同一次修改里完成。万一写盘只成功了一部分（例如节点文件写好了、资料库文件没写成），会报错，但内存里两边已经一致，下一次成功保存时补齐；只有在那之前就退出，才可能留下不一致。
- **名字**：编辑框下方实时显示解析结果（协议、地址、端口和保存后的名字），和保存时用同一个规则：
  - 链接里**写了**名字（`#` 后面，或 vmess 链接里的名字），并且和原链接里的相同时，节点**保留现在的名字**。导入时为了区分同名节点，可能已经把它改成了「HK 2」这样的名字，只改端口不应该把它改回去。
  - 链接里的名字改了，就用新名字；链接没写名字时，按导入的规则用它现在指向的地方起一个（协议 + 地址 + 端口），改了端口名字也跟着变。
- **没有原文的节点**：旧版本导入的节点，或者从 Clash / sing-box 配置导入的节点，没有保存原文。编辑框是空的，提示粘贴一条新链接来替换它。

### 2.2 节点身份

分流里对节点的选择按「订阅 + 节点名」记（第 1 节）。

- 链接改了但节点名没变：主出口、分流项、例外、兜底里的选择，以及「不参与自动选择」和地区设置，全部保留。
- 节点名也改了：这些地方一起改成新名字，不会变成「节点不在了」。手动设置过的地区跟着节点走，不会被新名字里识别出的地区替换。
- 节点身份就是「导入 + 名字」：新名字如果是这份导入里一个已经删除的节点的名字，分流里对那个节点的选择和它的设置（「不参与自动选择」、地区）会归到改名后的节点上，和订阅更新时服务商换上一个同名节点的处理一致。

### 2.3 验收

- 从分享链接导入的节点保存了原文；订阅和配置文件导入的行为不变。
- 编辑导入节点：改端口后生效；只改端口时保留导入时起的名字，没写名字的链接按新地址重新起名；改名后各处的选择和手动设置的地区跟着走；错误的链接、多条链接、重名或重复的节点都不保存，原节点不变；订阅节点不能编辑，也不保存原文。
- 界面：节点菜单和订阅卡片菜单的入口只对导入的节点出现；卡片菜单列出导入里的全部节点；预览显示保存后的名字；没有原文时的提示；两种语言。

## 3. 中转（链式代理）

节点可以配置为先通过另一个直连节点再连接到自身服务器，支持两跳中转。

### 3.1 两层模型与防循环

- **普通节点**：直接连接自身服务器，既可以作为出口承载流量，也可以作为其他节点的中转。
- **中转节点（落地节点）**：连接自身服务器时先经由一个前置中转，**不能再被其他节点选作中转**。这样任意连接的跳数最多为两跳，不存在循环或嵌套。
- **反向保护**：当某个节点（或订阅中未单独设为直连的节点）已被其他节点或订阅指定为中转时，不能再给它设置中转，界面会说明依赖它的对象。

### 3.2 配置入口与优先级

生效顺序从高到低为：**单节点覆盖 > 订阅默认经由 > 服务商配置声明 > 直接连接**。

- **单节点**：节点页卡片菜单中的「设置中转…」，可选择跟随订阅/服务商默认、直接连接、自动选择（最快直连节点）、地区自动（指定地区最快直连节点）或指定某个直连节点（默认开启「不可用时临时用同地区最快节点」）。
- **订阅默认经由**：添加或编辑订阅/导入时，在「参与自动选择」下方可设置整份订阅的默认经由。
- **服务商自带两跳**：导入 Clash（`dialer-proxy`）或 sing-box（`detour`）配置时，自动识别指向普通节点或节点组的两跳声明；超过两跳、循环或指向不存在目标的条目会跳过并记录原因。
- 首次为节点或订阅开启中转时，会自动关闭「参与自动选择」，避免中转节点在未察觉的情况下被日常自动选路使用；用户仍可手动重新开启。

### 3.3 配置生成与不可用兜底

- 中转用的自动组（`relay-auto`、`relay-region-*`、`relay-pin-*`）只包含普通直连节点，按需生成；没有任何中转节点时生成的配置与之前完全一致。
- 中转不可用时**绝不静默回退为直连**：
  - 指定中转节点失效且开启同地区临时替代时，切到同地区最快的直连节点并在界面提示。
  - 指定中转消失且无同地区直连节点，或中转地区/自动池为空时，该节点的 `detour` 指向 `relay-blocked`（`block` 出口），连接直接失败并在节点页给出警告横幅与重新选择入口。
